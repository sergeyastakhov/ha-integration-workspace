# tools

Вспомогательные скрипты рабочей области. Не публикуются в PyPI и не входят ни в одну
интеграцию: это инструменты разработки.

## publish.py

Публикует компонент рабочей области в его собственный репозиторий GitHub.

```bash
python tools/publish.py list
python tools/publish.py ha-mtdx62 --message "Add the live check checklist" --dry-run
python tools/publish.py ha-mtdx62 --message "Add the live check checklist"
```

Что делает:

1. находит компоненты сам: `integrations/<domain>` → `ha-<domain>`, `libraries/<name>` → `<name>`;
2. клонирует репозиторий в `.scratch/repos/<repo>` или обновляет его через `--ff-only`;
3. приводит рабочее дерево клона к содержимому папки рабочей области;
4. делает обычный коммит и отправляет его в `main`.

Опубликованная история не переписывается: ни `--force`, ни пересоздания коммитов. Если в клоне
есть коммит, который не уехал (например, тогда не было токена), следующий запуск его отправит, а
не сообщит «нечего публиковать».

Токен берётся из `GITHUB_TOKEN` или `GH_TOKEN` и не попадает в командную строку: git получает его
через переменные окружения `GIT_CONFIG_*`. Владелец репозитория — `GITHUB_OWNER`, по умолчанию
`sergeyastakhov`; автор коммита — `GIT_AUTHOR_NAME` и `GIT_AUTHOR_EMAIL`.

## Что здесь не лежит

Релизы (теги, заметки, публикация на PyPI) выполняются workflow в репозиториях компонентов:
`.github/workflows/publish.yml` библиотеки и `.github/workflows/ci.yml` интеграции. Локальные
скрипты для этого держите в `.scratch/`, в репозиторий рабочей области они не попадают.
