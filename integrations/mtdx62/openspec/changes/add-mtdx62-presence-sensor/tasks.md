- [ ] 1.1 Создать скелет репозитория интеграции: `custom_components/mtdx62/`, `manifest.json` (`domain`, `name`, `version`, `config_flow`, `dependencies: ["modbus"]`, `connectivity: ["modbus"]`, `integration_type: device`, `iot_class: local_polling`, `issue_tracker`, `categories`, `quality_scale: bronze`, `loggers`), `hacs.json`, `pyproject.toml`, `.pre-commit-config.yaml`, `.gitignore` [infra]
- [ ] 1.2 Вынести константы, список платформ и вспомогательную функцию построения параметров связи (`ModbusTcpParams` / `ModbusSerialParams`), чтобы мастер и настройка использовали одно и то же [spec:mtdx62-connection#Соединение не принадлежит интеграции]
- [ ] 1.3 Реализовать мастер: меню «Сеть» / «Последовательный порт», формы с значениями по умолчанию (502, 9600, нечёт, 1 стоп-бит, адрес 1), подсказки к полям и тексты ошибок в переводах [spec:mtdx62-connection#Значения по умолчанию для параметров связи]
- [ ] 1.4 Реализовать общую проверку ввода для обоих шагов: адрес 1–247, чтение с датчика через временный юнит, отказ при недоступном датчике и при конфликте параметров связи, уникальный идентификатор записи, заголовок записи из модели [spec:mtdx62-connection#Проверка связи до создания записи]
- [ ] 1.5 Реализовать шаг изменения параметров связи с сохранением сущностей устройства [spec:mtdx62-connection#Изменение параметров связи]
- [ ] 1.6 Реализовать `async_setup_entry`: получить юнит через `async_get_unit`, создать объект устройства из библиотеки, поднять координатор, выполнить первое обновление, сохранить данные в `runtime_data`, подключить платформы; реализовать `async_unload_entry` без закрытия соединения [spec:mtdx62-connection#Выгрузка записи]
- [ ] 1.7 Реализовать координатор: интервал 5 секунд, счётчик неудач подряд с порогом три, однократные записи в лог о потере и восстановлении связи, отсутствие перезагрузки записи при обрыве [spec:mtdx62-connection#Обрыв связи во время работы]
- [ ] 1.8 Тесты мастера: оба вида связи, ошибка подключения, адрес вне диапазона, повторное добавление того же датчика, конфликт параметров связи, изменение параметров; покрытие формы настройки 100 % [spec:mtdx62-connection#Один датчик — одна запись конфигурации]
- [ ] 1.9 Тесты жизненного цикла: недоступный датчик при старте даёт повторную попытку настройки, выгрузка и повторная загрузка записи, обрыв и восстановление связи на mock-бэкенде [spec:mtdx62-connection#Недоступный датчик при запуске]
- [ ] 1.10 Прогнать качественный шлюз интеграции: `ruff`, `mypy --strict`, `pytest` с покрытием [infra]

## 2. Устройство и сущности

- [ ] 2.1 Реализовать базовый класс сущностей датчика: общие `DeviceInfo` (производитель, модель из данных записи, версия приложения), `has_entity_name`, стабильный идентификатор сущности от идентификатора записи и ключа сущности [spec:mtdx62-presence#Стабильный идентификатор сущности]
- [ ] 2.2 Реализовать платформу `binary_sensor`: сущность присутствия с классом `occupancy`, без собственной фильтрации, `unavailable` при недоступности [spec:mtdx62-presence#Состояние не фильтруется интеграцией]
- [ ] 2.3 Реализовать платформу `sensor`: освещённость в люксах и расстояние в сантиметрах с переводом из метров библиотеки, расстояние выключено по умолчанию [spec:mtdx62-environment#Расстояние выключено по умолчанию]
- [ ] 2.4 Реализовать диагностические сущности: состояние устройства перечислением по таблице кодов (включая «неизвестный код»), версия приложения и радара, категория «диагностика», выключены по умолчанию; заполнить `icons.json` [spec:mtdx62-device-health#Диагностические сущности версий прошивки]
- [ ] 2.5 Задать `PARALLEL_UPDATES` в каждом модуле платформы и убедиться, что опрос идёт только через координатор [spec:mtdx62-presence#Один опрос на датчик в момент времени]
- [ ] 2.6 Тесты платформ: снимки состояний и реестра сущностей, появление и уход человека, недоступность вместо «никого нет», переименование устройства без смены идентификатора [spec:mtdx62-presence#Недоступность датчика]
- [ ] 2.7 Тесты реестра устройств: производитель, модель и версия попадают в карточку устройства [spec:mtdx62-connection#Модель датчика задаётся пользователем]
- [ ] 2.8 Прогнать качественный шлюз: `ruff`, `mypy --strict`, `pytest`, покрытие не ниже 95 % [infra]
