# Proposal

## Why

Библиотека `mtdx62-modbus-library` вышла на PyPI, и картинки в её описании оказались битыми: PyPI
показывает их через прокси `pypi-camo.freetls.fastly.net`, который на относительный путь отвечает
`404 Bad url scheme`. В README библиотеки все шесть изображений были записаны как
`docs/images/device-*.webp`.

Это не ошибка одного README, а свойство площадки: PyPI берёт описание из метаданных пакета и
разрешает относительные ссылки относительно `pypi.org`, а не относительно репозитория. Значит
правило нужно общее: любая библиотека, публикуемая на PyPI, обязана иметь абсолютные ссылки в
README, а проверка должна стоять в CI, чтобы это не всплывало через неделю после релиза.

Заодно фиксируется следствие, которое иначе каждый раз застаёт врасплох: описание на PyPI — это
снимок из загруженного пакета, поэтому исправление README видно только в следующем релизе, даже
если файл в репозитории уже правильный.

## What Changes

- Новая сквозная возможность `conventions/pypi-packaging`: требования к README библиотеки как к
  описанию пакета.
- В библиотеке `mtdx62-modbus-library`: все ссылки в README становятся абсолютными, в CI
  добавляется проверка, которая падает на относительной ссылке, выпускается 0.4.1 с исправленным
  описанием.
- Карта сквозных правил в `AGENTS.md` получает строку про README для PyPI.

## Capabilities

### New Capabilities

- `conventions/pypi-packaging`: что должно быть верно для README библиотеки, который PyPI
  показывает как описание пакета.

### Modified Capabilities

Нет.

## Impact

- Библиотека: README, скрипт проверки, workflow, версия 0.4.1 и заметки.
- Будущие библиотеки получают правило до первого релиза, а не после первого сломанного описания.
- Интеграции не затронуты: у них другое описание и другая площадка.
