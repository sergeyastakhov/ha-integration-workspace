# Proposal

## Why

Датчики присутствия MTD062-MB (5.8 ГГц) и MTD262-MB (24 ГГц) умеют отличать неподвижного
человека от пустой комнаты по дыханию и микродвижениям, но Home Assistant их не знает: у
устройств есть шина RS485 с протоколом Modbus, а готовой интеграции нет. Без неё датчик
бесполезен для автоматизаций — его единственный выход либо сухой контакт, либо регистры,
которые никто не читает.

Сейчас удобный момент начать: протокол описан производителем полностью (карта регистров,
функции, примеры кадров), документация собрана в `references/mtdx62/`, а правила проекта в
`AGENTS.md` уже задают процесс и планку качества. Интеграция стартует как custom-компонент для
Marketplace, но сразу пишется по правилам Core.

## What Changes

- Появляется интеграция `mtdx62` для датчиков присутствия MTD062-MB и MTD262-MB по Modbus.
- Пользователь настраивает подключение к шине: последовательный порт (RTU) либо TCP-шлюз
  (Modbus TCP), с параметрами обмена.
- На одной шине можно завести несколько датчиков: каждому задаётся свой адрес и имя, все они
  становятся отдельными устройствами Home Assistant.
- Для каждого датчика появляются сущности:
  - бинарный датчик присутствия (`occupancy`) — главная сущность;
  - датчик освещённости в люксах;
  - датчик расстояния до цели (по умолчанию выключен);
  - диагностические сущности: код состояния устройства, версия приложения и радара.
- Интеграция опрашивает датчики одним запросом на устройство и корректно переживает пропадание
  связи: сущности становятся `unavailable`, в лог пишется одна запись о потере и одна о
  восстановлении.
- Добавляется скачивание диагностики с вырезанными секретами (адреса, MAC-код).
- Протокол выносится в отдельную библиотеку `mtdx62`, которая публикуется на PyPI и покрывается
  своими тестами; интеграция зависит от неё и содержит только связку с Home Assistant.
- Первая версия **не пишет** параметры датчика (чувствительность, дальность, задержки, порог
  освещённости). Чтение и запись параметров — отдельное изменение: см. «Что отложено».

### Что отложено и почему

| Отложено | Причина |
|---|---|
| Запись параметров датчика (чувствительность, дальность, задержки, порог освещённости) | Требует отдельного решения по модели сущностей (`number`/`select` с ограничениями и шагом), проверки на живом устройстве и отдельного набора сценариев. Смешивать с первым выпуском — значит удвоить объём проверок до первого полезного результата. |
| Активный отчёт устройства (push) вместо опроса | Документация не описывает поведение при переполнении и потерю кадров; выигрыш по задержке при опросе раз в 5 секунд незначителен. Оставляем как возможную оптимизацию после проверки на живом устройстве. |
| Repair issues для неисправностей радара | Неисправность железа пользователь не может устранить из интерфейса; достаточно диагностической сущности состояния и записи в логе. |
| Автообнаружение (zeroconf/DHCP/USB) | Устройство — пассивный Modbus-слейв за шиной или шлюзом, само о себе не объявляет. |

## Capabilities

### New Capabilities

- `mtdx62-connection`: подключение к шине Modbus (RTU через последовательный порт или TCP через
  шлюз), добавление и удаление датчиков на шине, изменение параметров подключения, корректная
  выгрузка записи и восстановление после потери связи.
- `mtdx62-presence`: сущность присутствия человека и её доступность — то, ради чего интеграция
  существует.
- `mtdx62-environment`: освещённость и расстояние до цели как сопутствующие измерения.
- `mtdx62-device-health`: состояние устройства, версии прошивок и диагностика для разбора проблем.

### Modified Capabilities

Нет: `openspec/specs/` пока пуст, это первое изменение в проекте.

## Impact

- **Новые репозитории**: `libraries/mtdx62` (Python-библиотека протокола, публикуется на PyPI) и
  `integrations/mtdx62` (custom-компонент `custom_components/mtdx62`, отдельный репозиторий GitHub).
- **Home Assistant**: новых зависимостей Core не появляется. Интеграция требует Python 3.14 и
  Home Assistant 2026.11+; `requirements` — только `mtdx62` и `pyserial-asyncio`.
- **Оборудование**: датчики в исполнении RS485, подключённые через USB-RS485 адаптер либо
  TCP-шлюз (например, USR-TCP232, Moxa).
- **Пользователи Marketplace**: установка через Marketplace, затем «Добавить интеграцию» → MTDx62.
- **Quality Scale**: изменение закрывает правила Bronze (`config-flow`,
  `config-flow-test-coverage`, `test-before-configure`, `test-before-setup`, `unique-config-entry`,
  `entity-unique-id`, `has-entity-name`, `runtime-data`, `appropriate-polling`, `common-modules`,
  `dependency-transparency`, `brands`, `docs-*`) и часть Silver (`config-entry-unloading`,
  `entity-unavailable`, `log-when-unavailable`, `parallel-updates`, `test-coverage`).
  Достижимый tier после этого изменения — **Bronze**, с прицелом на Silver в следующем изменении
  (нужны `docs-configuration-parameters` и `reauthentication-flow`/`action-exceptions` в части
  параметров).
- **Домен**: `mtdx62`. Не совпадает ни с одним доменом Core; проверка — задача в `tasks.md`
  (запрос `home-assistant.io/integrations/mtdx62` должен отдавать 404, а `homeassistant/components/mtdx62`
  в Core отсутствовать).
