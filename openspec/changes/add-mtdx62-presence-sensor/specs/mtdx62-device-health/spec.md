# Spec Delta

## Purpose

Когда датчик ведёт себя странно — не видит человека, постоянно показывает присутствие или не
отвечает — пользователю и сопровождающему нужно понять причину. Для этого интеграция показывает
состояние самого устройства, версии прошивок и выгружает диагностику.

## ADDED Requirements

### Requirement: Диагностическая сущность состояния устройства

Для каждого добавленного датчика интеграция SHALL создавать сущность состояния устройства с
категорией «диагностика», выключенную по умолчанию.

Значение берётся из input-регистра `0x0003` и переводится в понятный текст по таблице:

| Код в регистре | Состояние |
|---|---|
| 0 | Исправен |
| 1 | Ошибка самопроверки программы |
| 3 | Прочая неисправность |
| 4 | Неисправность радарного модуля |
| 5 | Неисправность связи RS485 |
| 6 | Неисправны радар и RS485 |
| другое | Неизвестный код |

#### Scenario: Устройство исправно

- **WHEN** датчик отдаёт в регистре `0x0003` значение 0
- **THEN** диагностическая сущность состояния показывает «Исправен»

#### Scenario: Неисправность радара

- **WHEN** датчик отдаёт в регистре `0x0003` значение 4
- **THEN** диагностическая сущность состояния показывает «Неисправность радарного модуля»

#### Scenario: Неизвестный код состояния

- **WHEN** датчик отдаёт в регистре `0x0003` значение 9
- **THEN** диагностическая сущность состояния показывает «Неизвестный код» и остаётся доступной,
  а не становится `unavailable`

### Requirement: Диагностические сущности версий прошивки

Интеграция SHALL создавать диагностические сущности версии приложения и версии радарного модуля,
выключенные по умолчанию.

Версия собирается из двух регистров: старший регистр — в input-регистрах `0x0004` и `0x0006`,
младший — в `0x0005` и `0x0007`. Значение показывается как строка вида `1.2.3`.

#### Scenario: Версии прошивки

- **WHEN** датчик отдаёт `0x0004 = 0x0001`, `0x0005 = 0x0203`, `0x0006 = 0x0000`, `0x0007 = 0x0102`
- **THEN** сущность версии приложения показывает `1.2.3`, а сущность версии радара — `0.1.2`

### Requirement: Сведения об устройстве в реестре

Интеграция SHALL заполнять в реестре устройств производителя («Zhejiang Oujue Electronic
Technology»), модель (выбранную пользователем при добавлении), а также версию прошивки, когда
она прочитана.

#### Scenario: Карточка устройства

- **WHEN** пользователь открывает страницу устройства
- **THEN** в ней указаны производитель, модель и версия приложения

### Requirement: Выгрузка диагностики

Интеграция SHALL поддерживать скачивание диагностики для записи конфигурации и для отдельного
устройства.

В диагностике MUST быть: параметры транспорта, список устройств с их адресами и состоянием,
текущие значения регистров и версии. Из диагностики MUST быть вырезаны значения, позволяющие
идентифицировать конкретное место: код MAC устройства и путь к последовательному порту
сохраняются в виде признака того, что значение задано, без самого значения.

#### Scenario: Скачивание диагностики записи

- **WHEN** пользователь скачивает диагностику записи, в которой два устройства
- **THEN** файл содержит оба устройства с адресами, моделями, состояниями и версиями, а код MAC
  заменён на указание, что он скрыт

#### Scenario: Скачивание диагностики устройства

- **WHEN** пользователь скачивает диагностику одного устройства
- **THEN** файл содержит только данные этого устройства и его текущие значения регистров

### Requirement: Сообщение о неисправности в журнале

Если датчик сообщает код неисправности, отличный от 0, интеграция MUST записывать это в лог
один раз при появлении неисправности и один раз при её исчезновении, а не на каждом опросе.

#### Scenario: Появилась и исчезла неисправность

- **WHEN** датчик пять опросов подряд сообщает код 4, а затем код 0
- **THEN** в логе появляется одна запись о неисправности и одна запись о её устранении
