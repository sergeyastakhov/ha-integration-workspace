# diagnostics

## Purpose

Единое правило поддержки пользователей: у каждой интеграции проекта есть скачиваемая диагностика,
и она не выдаёт того, что позволяет найти конкретный дом или взломать устройство.

## Requirements

### Requirement: Диагностика доступна для каждой интеграции

Интеграция SHALL поддерживать скачивание диагностики — для записи конфигурации и, если интеграция
создаёт устройства, для отдельного устройства.

#### Scenario: Скачивание диагностики

- **WHEN** пользователь запрашивает диагностику записи конфигурации
- **THEN** файл формируется и содержит сведения, достаточные для разбора проблемы без доступа к
  системе пользователя

### Requirement: Секреты и идентификаторы вырезаются

Диагностика MUST NOT содержать учётные данные, токены, пароли и ключи. Идентифицирующие значения —
код MAC, серийный номер, путь к последовательному порту, координаты — SHALL заменяться указанием,
что значение скрыто.

#### Scenario: Выгрузка при настроенном последовательном порте

- **WHEN** интеграция работает через последовательный порт и пользователь скачивает диагностику
- **THEN** путь к порту в файле заменён пометкой о скрытии, а не показан целиком

### Requirement: Диагностика формируется и при недоступном устройстве

Если устройство не отвечает, диагностика SHALL всё равно формироваться: в ней остаются параметры
подключения и пометка о том, что данные получить не удалось.

#### Scenario: Молчащее устройство

- **WHEN** пользователь скачивает диагностику, а устройство не отвечает
- **THEN** файл формируется, содержит параметры подключения и явную пометку об отсутствии данных

### Requirement: Причина проблемы видна в диагностике

Диагностика SHALL содержать состояние обмена с устройством: последние ошибки, версии прошивки,
а для устройств с регистрами — их текущие значения в сыром виде.

#### Scenario: Разбор проблемы с показаниями

- **WHEN** пользователь сообщает о неверных показаниях
- **THEN** в диагностике есть сырые значения, по которым можно воспроизвести разбор у себя
