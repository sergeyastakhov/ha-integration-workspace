# conventions/pypi-packaging Specification

## Purpose

Правила описания пакета на PyPI: README библиотеки — это и есть страница пакета, поэтому все ссылки в нём абсолютные, картинки доступны по прямой ссылке, а исправление описания видно только в следующем релизе. Проверка ссылок стоит в CI библиотеки.

## Requirements

### Requirement: README библиотеки — это описание пакета

README библиотеки SHALL быть текстом, который PyPI показывает как описание пакета: он MUST
читаться без репозитория, без локальных файлов и без авторизации.

Исправление README видно на PyPI только в следующем релизе: описание берётся из метаданных
загруженного пакета, а не с ветки. Поэтому правка README SHALL попадать в релиз, а не жить
отдельным коммитом.

#### Scenario: Читатель открывает страницу пакета

- **WHEN** пользователь открывает страницу `mtdx62-modbus-library` на PyPI
- **THEN** он видит установку, использование, картинки и ссылки, и ни одна ссылка не ведёт на
  страницу PyPI вместо нужного документа

#### Scenario: README исправлен после релиза

- **WHEN** ссылка в README исправлена, а версия не поднята
- **THEN** описание на PyPI остаётся прежним, и это считается незакрытой работой

### Requirement: Ссылки в README абсолютные

Каждая ссылка и каждое изображение в README SHALL быть абсолютными: `https://`, `mailto:` или
якорь внутри страницы.

Относительные пути MUST NOT использоваться. PyPI разрешает их относительно `pypi.org`, а
изображения заворачивает в прокси, который на относительный путь отвечает `404 Bad url scheme`.

#### Scenario: Картинка в README

- **WHEN** README ссылается на изображение из `docs/images/`
- **THEN** в тексте стоит `https://raw.githubusercontent.com/<owner>/<repo>/main/docs/images/...`,
  и картинка видна на странице пакета

#### Scenario: Ссылка на документ

- **WHEN** README ссылается на документ из репозитория
- **THEN** в тексте стоит абсолютный адрес `https://github.com/<owner>/<repo>/blob/main/...`

#### Scenario: Относительная ссылка

- **WHEN** в README остаётся `docs/DEVICE-FACTS.md` без схемы
- **THEN** на PyPI читатель попадает на несуществующую страницу `pypi.org`, а проверка в CI
  считает это ошибкой

### Requirement: Проверка ссылок стоит в CI

CI библиотеки SHALL проверять README перед публикацией и MUST падать, если нашлась относительная
ссылка.

Проверка SHALL называть offenders, чтобы автор правил их, а не искал глазами.

#### Scenario: Правка со относительной ссылкой

- **WHEN** pull request добавляет в README ссылку без схемы
- **THEN** проверка падает, перечисляет найденные пути и не пропускает релиз

#### Scenario: Все ссылки абсолютные

- **WHEN** в README нет относительных ссылок
- **THEN** проверка проходит и называет число проверенных ссылок
